# Contributing to selectry repositories

Thank you for taking the time to contribute. Repository-specific guidance takes precedence over this organization-wide baseline.

## Before you start

1. Search existing issues and pull requests to avoid duplicate work.
2. For a substantial change, open an issue or discuss the approach with the maintainers first.
3. Never include credentials, personal data, customer data, candidate data, or confidential company information in an issue, commit, fixture, screenshot, log, or pull request.

## Pull requests

- Keep the change focused and explain the problem it solves.
- Link the relevant issue or work item.
- Describe validation performed and any operational or security impact.
- Update documentation when behavior or an interface changes.
- Request review from the appropriate maintainers and address review feedback.
- Use clear commit messages and keep generated or unrelated files out of the change.

## Security issues

Do not open a public issue for a suspected vulnerability. Follow our [security policy](SECURITY.md) instead.

## Conduct

Participation in selectry repositories is governed by our [Code of Conduct](CODE_OF_CONDUCT.md).
